# Realtime module contract

`createRealtimeServer` owns the Hocuspocus WebSocket listener. The API composition root injects validated runtime config, verified identity lookup, session persistence, invitation membership lookup, and structured logging. In local development the listener defaults to `127.0.0.1:4001`; production must explicitly configure both `REALTIME_HOST` and `REALTIME_PORT`. A room name is exactly a server-issued 24-character session id.

Each upgrade must include the exact configured Whiteboard `Origin` and a valid HttpOnly `wb_session` cookie. Authentication resolves the principal on the server, checks an active session and owner/accepted membership, then records a MongoDB connection lease. Neither a client role nor invitation token is trusted as room credentials. All clients use Hocuspocus stateless messages for Whiteboard semantic board commands; raw Yjs document updates are rejected for every role, so a client cannot bypass board authorization or durable commit. Viewers cannot submit edits. The server rewrites awareness identity fields from the verified membership.

The session document stores durable membership separately from live connection leases. The owner plus at most 24 invitees (25 members total) are admitted atomically when a verified one-time invitation is accepted. Pending invitations do not reserve a member slot. Disconnect releases only the connection lease; membership remains until the session ends or membership is explicitly revoked. Sessions have no time-based expiry. A member may reconnect from another browser/device while the session is Active. Connections refresh every 30 seconds with a 90-second lease; an expired lease or three consecutive storage-refresh failures closes only that socket. After owner end commits, connected invitees receive a `session:ended` stateless event immediately before their socket closes; the app shows an end-session dialog, detaches them from the ended room, and keeps the current board open as a local copy. Room joins and edits also fail the active-session check. Owner removal revokes durable membership before immediately closing the member's live socket; later room joins and edits are denied.

An Editor command carries a UUID action id, base sequence and up to 512 typed changes. The server limits each socket to 600 messages per 60-second window, validates each command, rechecks current membership/role, and delegates persistence to the session repository. MongoDB commits the operation, updated board, shared-history stacks and incremented sequence in one transaction. Only after commit does the server broadcast the resulting board, sequence, and Undo/Redo availability to the Hocuspocus room. Same-property edits are last accepted write wins; independent property edits merge onto the latest stored board. Repeated action IDs are idempotent for their original actor.

Before a live-session create or edit is persisted, Whiteboard measures the canonical BSON payload. The board/snapshot and each operation are capped at 8 MiB. Over-limit create requests receive `413 board_too_large`; over-limit live edits are rejected as `document_too_large` before the transaction commits, leaving the shared board and sequence unchanged.

Shared history stores up to 500 accepted meaningful actions per session. Forward operations store their inverse and per-field/object guards. Owner and Editor Undo/Redo requests get their target action from the persisted stack, never from a client-selected target. A guarded inverse that no longer matches current board state is rejected with `unsafe_inverse`; empty stacks return `history_unavailable`. Both errors leave board and stack unchanged. Undo/Redo commands use the regular 600-message-per-minute socket limit and are committed/broadcast as sequenced operations, so recovery replay includes them.

The app uses one Hocuspocus room per server-issued session ID, maintains an optimistic pending queue in session-scoped localStorage, and reconciles from the latest server board on connect. If transport drops while an edit is in flight, the app clears only the volatile in-flight marker and retains the queued edit's stable action ID; after reconnect it requests canonical state and retries the edit, so MongoDB idempotency resolves an acknowledgement lost across the disconnect. Queue entries are not proof of persistence; the UI reports queued edits and keeps rejected/degraded commands locally. Replay is strict FIFO; when the oldest queued edit is rejected or requires review, later edits stay queued until the user explicitly retries, preventing them from overtaking the unresolved conflict. The device queue is capped at 500 edits and 1 MB; exceeding either limit refuses the next edit before updating the board. Edits older than seven days remain stored but require an explicit confirmation before retry, because a stale replay can replace newer values. On reconnect/restart, the session repository reads the latest board snapshot and replays contiguous later operation records. A board snapshot is written every 100 accepted operations. Owner closure removes invitations, memberships, operations, snapshots, and the ended session record after access is revoked; failed cleanup leaves an ended marker so the owner can retry.

The same Live Collaboration session supports Editor and Viewer invitations. Viewers can navigate their own canvas view but cannot alter board objects; this is enforced both in the UI and by server authorization of board edits/history actions. Editors and the Owner can edit. There is no shared presentation viewport or Presentation mode. Owner connection state is broadcast on connect/disconnect for participant status.

Hocuspocus awareness carries transient participant presence. The server overwrites each awareness `user` with verified membership display name and role, limits each inbound update to one client state and 1,200 updates per socket per 60 seconds, and limits forwarded presence to that identity plus an optional bounded cursor. Excess updates/states are dropped and logged once per threshold/anomalous connection. The app renders connected names/initials and cursors for all session roles; awareness is not part of the board snapshot, operation log, XML, or edit history. Awareness expiry removes disconnected clients; the standard Yjs awareness timeout is 30 seconds. Session room scoping applies to all awareness broadcasts.

Still open: multi-participant browser verification, stale-edit conflict behavior, room isolation and Viewer tamper tests, participant removal/end-session socket revocation, shared Undo/Redo behavior across browsers, production mail and deployment limits. The local `whiteboard:test:realtime` integration passed on 2026-10-20 with separate Owner and Editor identities: invitation acceptance, authenticated Hocuspocus room membership, and two-way accepted edit broadcasts were verified, and the temporary session was ended in cleanup. Browser UI behavior is not covered by that script. Browser-provider reconnect was verified locally after an isolated API/realtime process restart: an offline queued edit synced once and the board contained two objects without duplication. An authenticated Hocuspocus protocol client also recovered a persisted semantic edit after restart; direct MongoDB transaction/replay validation for Undo/Redo passes. The current transport is not release-ready until the remaining checks pass.
