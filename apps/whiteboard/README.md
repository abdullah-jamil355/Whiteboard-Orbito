# Whiteboard

Whiteboard is a standalone, local-first board workspace. Normal boards are not automatically saved to the cloud.

## Run locally

- Requirements: Node.js 20.19 or newer and pnpm 11.19, installed at the repository root.
- From the repository root, run `node codebase/cli/repo.mjs run whiteboard:dev`.
- Open `http://localhost:3000`. Next.js may select the next available port if 3000 is occupied; use the URL printed by the development server.
- No environment variables, Squid login, Squid API, MongoDB, or other external service is required for standalone local use.
- For owner sign-in and server-backed sessions, copy `.env.example` to `.env.local`, set `NEXT_PUBLIC_WHITEBOARD_API_ORIGIN` to the API origin, `NEXT_PUBLIC_WHITEBOARD_REALTIME_URL` to the Hocuspocus WebSocket URL (local default `ws://localhost:4001`), and configure API `WEB_ORIGIN` to the exact Whiteboard app origin (including its selected port). The API and realtime server require MongoDB; regular local boards remain usable without them.
- A participant can return on another browser by signing in with the same verified email. The workspace lists that identity's active sessions; choose **Rejoin** to restore the server board. A removed participant will not see the session and cannot reopen it with an old session ID.
- Live MongoDB persistence has an 8 MiB BSON safety budget per board/snapshot and accepted operation. The app rejects oversized live content with an actionable message; local XML boards are not subject to this server persistence limit.
- To verify a production build, run `node codebase/cli/repo.mjs run whiteboard:build` from the repository root.
  - For a real two-identity Hocuspocus sync check, start the local API/realtime service with development MongoDB, then run `pnpm --dir apps/whiteboard run test:realtime`. It uses the loopback-only development mailbox and reusable `.invalid` test identities, verifies each HTTP identity cookie before connecting, creates a temporary session, verifies Owner-to-Editor and Editor-to-Owner edits, and ends the session. A `429` reports the server's `Retry-After`; wait that long before rerunning because the API rate-limits magic-link requests. Never point it at a deployed API.

## Appearance

Use the moon/sun button in the workspace header to switch between light and dark
appearance. The choice is saved in this browser and restored on the next visit. Dark
appearance changes the workspace chrome and controls; the drawing surface stays light
so existing board colors remain consistent.

On desktop, the workspace sidebar stays as a narrow icon rail and expands over the
workspace on hover or keyboard focus. It collapses when the pointer leaves and no
navigation item retains focus. On narrow screens, navigation remains a labeled row.

## Embedding boundary

The reusable board components and model are provided by `@workspace/whiteboard`; the app-owned `features/board` workspace composes them with local file, keyboard, and session actions. An embedding host can provide its own user/workspace context, permissions, theme, locale, and return navigation. Host-provided permissions are context only and are not authorization; the host server must enforce access.

## Start from a template

- Choose **Templates** to browse the built-in diagram catalog. Selecting one creates a separate board copy with new board and object IDs; edits to a copy do not change the built-in source.
- Nonblank templates start with larger, fuller diagrams that are centered to use most of the canvas; the blank page remains empty. Each included shape, label, and connector can be changed independently.
- Save a template-based board with **Save XML** to download its editable Whiteboard project file.
- Choose the **Pen tool**, then drag on the canvas to add a freehand stroke. Its weight starts at Thin; choose Medium or Thick when needed. Pen weight is independent from shape and line weights. Each completed stroke is one Undo action.
- Choose the **Eraser tool**, then drag across drawing content. Crossing a freehand stroke removes only the crossed portion and leaves the remaining pieces editable. Crossing a shape, text, line, arrow, or connector removes that whole object; removing a shape also removes its contained text and leaves its connected lines detached at their last positions. One drag is one Undo/Redo action. Objects outside the eraser path remain unchanged.
- Choose **Rectangle**, **Circle**, or **Diamond**, then drag on the canvas to add that editable shape. New shapes have no palette fill by default; on the dark canvas that no-fill area matches the canvas surface and masks grid lines. New shape outlines start at Thin. You can change the selected shape's outline weight, color, and fill independently; changing one shape never changes other shapes. Drag a selected shape's corner handle to resize it; circles keep equal width and height and retain their proportions as the canvas resizes. Rotation is not available in V1.
- The drawing area is an unbounded workspace: pan in every direction and keep placing or moving objects beyond the initial view. Horizontal and vertical rulers show world coordinates and stay fixed at the top and left edges while the board moves. New boards and templates open at 100% zoom, centered on the board origin. Hover over a shape while using **Select** to show directional quick-connect handles. Click a handle to automatically connect to the nearest shape in that direction, or drag it to another shape to choose the target. Choose **Connector** to draw an automatic right-angle connector; dropping on a shape attaches the endpoint. Choose **Line** or **Arrow** and drag between shapes to attach either or both endpoints. Connected lines, arrows, and connectors stay attached when a bound shape moves or resizes. Connector bends are automatic and cannot be dragged in V1.
- Choose **Text**, then click a blank area to add standalone text or click a shape to add text inside it. A shape label starts as a compact transparent editor and grows as you type, up to the shape's inner bounds. Use **Select** to interact with existing objects: a single click selects the exact text, shape, stroke, line, arrow, or connector; double-click text to edit that label. Selected objects can be dragged to move them. Text inside a shape stays attached to it when the shape moves.
- Select text to apply a palette color, including ink, blue, red, green, amber, teal, violet, or white. New lines, arrows, and connectors start at Thin and their weight setting is independent from pen and shape outline weights. Each existing board object keeps its own saved style.
- Pen strokes, shapes, text, lines, arrows, and connectors are rendered and saved as editable Whiteboard objects.
- In an authenticated session, edits are sent as server-validated semantic commands. The API durably commits each accepted operation to MongoDB before broadcasting the accepted board revision. While disconnected or when a write fails, the UI shows queued edits; queued local changes are not reported as server-saved. If a disconnect loses an edit acknowledgement, the queue keeps its stable action ID and retries after reconnect; the server's idempotency check prevents that retry from applying an already accepted edit twice. Replay is strict FIFO: a rejected/blocked queue head pauses later edits until the user retries the queue, so later edits cannot overtake an unresolved stale edit. The device queue is capped at 500 edits and 1 MB; a new live edit is refused before changing the board when it would exceed either limit. Entries older than seven days stay on-device and require explicit confirmation before retry because replay may replace newer changes. Multiple participant/browser verification is still a release gate.
- Use the Select tool to click an object, Shift-click to add or remove individual objects, or drag around a whole diagram on empty canvas to select the objects fully enclosed by the box. The light dotted selection outline follows each object's actual shape or path. Lines, arrows, and connectors show resize handles at their endpoints. Dragging a connected line, arrow, or connector moves the selected object and detaches endpoints whose shapes were not selected with it; endpoints stay attached when their shapes are included in the same selection. Shift+drag adds enclosed objects to the current selection. Drag any selected object to move the selected group together. Ctrl/Cmd+A selects every board object. You can also copy/cut/paste/duplicate/delete selections. Toolbar **Undo** and **Redo** or Ctrl/Cmd+Z and Ctrl/Cmd+Y reverse and reapply edits. On a local board, history is held in memory and resets when another board replaces it. In a live session, Owner and Editors use shared server history: Undo reverses the latest accepted participant action, Redo restores the latest undone action, and a new accepted edit clears Redo. The server keeps up to 500 undoable actions; unsafe inverses are rejected without changing the shared board. Keyboard shortcuts also include Ctrl/Cmd+C/X/V/D, Ctrl/Cmd+S, and Delete/Backspace. To operate objects with a keyboard, Tab to the drawing surface and continue through its objects. Arrow keys move the focused object by one canvas unit; Shift+arrow moves it by ten. The focused object has a visible yellow outline. Toolbar controls are keyboard-focusable buttons.
- The local board state (including whether changes are unsaved, whether XML download started, or whether saving failed) is announced as text to assistive technology; color is supplementary.
- Individual objects can be resized with their selection handles. Use Bring to Front and Send to Back to change object stacking; that order is preserved in saved XML.
- Use **Ctrl/Command + Plus** and **Ctrl/Command + Minus** to zoom from 25% to 400%, or use Reset canvas view to return to the centered 100% view. On desktop, hold Space and drag to pan; on touch devices, drag an empty part of the canvas. Touching an object still selects or moves that object. Camera position and zoom are local view state and are not stored in the board XML. The light graph-paper lines move with the camera, stay visible across the workspace, and remain hidden beneath shapes.

## Save and protect your work

- Use **Save XML** or press **Ctrl+S** ( **Command+S** on macOS) to start downloading an editable Whiteboard XML project file. Check your browser's download UI to confirm the file was saved where you expect; the app cannot verify that the browser finished writing it to disk.
- When opening a project or starting a new board while the canvas contains unsaved objects, choose **Save and continue**, **Discard changes**, or **Cancel**. An empty canvas is replaced directly without a save prompt. Cancel leaves the current board and its edits open. If the XML download cannot start, the current board stays open so you can retry or cancel.
- Closing the tab or navigating away from the app while there are unsaved changes invokes the browser's own warning. Browser wording and controls vary; use the Whiteboard Save action before leaving if you need to keep the latest changes.
- Importing an XML project does not replace the current board until the file has been read and validated. Invalid files show an error and leave the open board unchanged.

## Start a session

- Choose **Start live session** and enter the live board title. The current blank board, template copy, or opened Whiteboard XML is captured as the Live Collaboration session's starting board.
- A session starts Active immediately and has no time limit; it remains active until the owner ends it. Only the owner can rename or end it. Ending offers Download XML and End, End without downloading, or Cancel. The XML comes from the canonical server-accepted revision; after the download starts, the owner confirms ending separately so a canceled browser download can leave the session Active. If a newer edit arrives before closure, the session stays Active and the owner can download again. Connected invitees receive a session-ended popup and keep the current board open locally; download XML to preserve it, including any edits that had not synced before the session ended. If another tab already ended the session, the stale tab clears its session controls when the server reports it unavailable and leaves the local board open.
- Starting a session requires a verified email identity. The app requests a one-time link; in development, the API's loopback-only mailbox shows the link directly. The API stores an Active session in MongoDB and allows only its verified owner to read, rename, or end it. On reload, the same tab restores the initial server board snapshot when the owner session remains active.
- A session owner can connect the same Gmail address used for Whiteboard sign-in and send a private one-time invitation from the Invite participants panel, choosing Editor or Viewer for every participant. Invitations expire after 10 minutes. The owner can cancel pending invitations. Google OAuth requests only Gmail's send scope; refresh tokens are encrypted at rest. The optional shared Gmail App Password sender is for sign-in links only. Without Google OAuth configuration or an owner-connected Gmail account, invitation sending is unavailable; development sign-in links remain available through the API's loopback-only in-memory mailbox.
- Viewers have read-only access to board content but can navigate their own canvas view. Editors and the Owner can edit the shared board. No participant follows another person's viewport.
- In a live session, the participant strip shows connected member names, initials, and verified roles. Owner and Editor cursors are transient; Viewer cursors are never broadcast by the server. Presence disappears when awareness expires after disconnect and is never included in XML or board history.
- Shared Undo/Redo controls are enabled only for a connected Owner or Editor when no live edits are waiting for server acceptance. Unsafe undo/redo is rejected with an explanation; the board remains unchanged. Browser multi-participant verification remains a release gate.
- An invitee signs in using the invited email, enters a display name, and accepts the link. The server stores the accepted identity and fixed role. Same-tab reload restores the active session; signing in on another browser lists the same identity's active memberships, and the participant explicitly chooses **Rejoin**. Membership and current session access are checked server-side, so removal prevents both discovery and board access until a new invitation is accepted. Shared editing and room authorization are implemented, though multi-participant browser verification remains a release gate. The owner can list participants with roles and connection state, and remove invitees; removal revokes their membership before closing live sockets. The 25-member cap includes the owner plus up to 24 invitees. Ending the session closes the room and deletes temporary session/invitation/operation/snapshot data; failed cleanup remains inaccessible until the owner retries ending it. Sessions do not expire by time. Atlas backups follow their separately configured retention policy.
